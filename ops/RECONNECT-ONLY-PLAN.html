Reconnect, Only

One product: a card a day that reopens a relationship worth reopening, with a message you would actually send. Everything else in the app goes dormant in place, the install shrinks by gigabytes, onboarding becomes the list of things the card needs and nothing more, and the whole path gets walked again from a clean machine before anyone else installs it. The bar for "magical" is written down first so the retest can fail.

Inventory findings that change the plan

Four things the walk-through found before any design

First-load bug · needs your toggle

iMessage has not ingested a message since 31 August

The connectors daemon runs as a child of the app, so macOS attributes its Full Disk Access to the app's bundle identifier. The 30 August rename from com.hazlie.widget to io.intaglio.widget left the new identifier without the grant: the system grant table shows the old id allowed, the new id denied. Every one of about 95 daily passes since has failed with a fingerprint that hides the message, and nothing on screen said so. Fix is a toggle in System Settings → Privacy & Security → Full Disk Access, which only the owner can flip; the pane is open. Two lessons go into the plan: onboarding must verify the grant from the app process and re-verify after every update, and a source that fails on a streak must turn its tile amber, not stay "connected".

First-load bug · fix in progress

Gmail has never linked a single person

All 81,725 mail rows have an empty sender. The REST connector hands the raw From: header string to a normaliser that only accepts arrays, so it returns nothing, and its own comment claims the opposite. Since the 26 August switch from IMAP, every mail row is participant-less: the card's "wrote to you" gate has never seen a Gmail contact, and the investor pool starved partly for this reason. The parser fix is being written now with a test that fails on the old code. Existing rows cannot be repaired from the database, because only the empty lists were stored; mail is purged and re-pulled during the retest, which is when a re-pull was due anyway.

Onboarding teaches the wrong product

Today's onboarding demos chat and voice, then downloads a 2.5 to 4.7 GB model

The three screens are a typing demo into the orb, a "find your widget" spotlight, and a model tier picker. None of them mention a person. The model is required only if there is no other engine; with the owner's Claude subscription detected, the card path needs no local model at all. Onboarding becomes the prerequisite list below.

Onboarding

The prerequisite list, each with a check the app runs and a fix it offers

Six screens. Every one ends in a state the app has verified, from its own process, never from a shell. The last screen is the first card.

1Who this is for

One paragraph and one example card, built from placeholder text, so the owner knows what they are setting up. Founder or investor mode chosen here; "any" is the default.

2Your messages

Full Disk Access for iMessage, Contacts, Calendar. The app opens the right Settings pane, polls the grant from the app process, and shows the row count as it lands. Check: chat.db readable and Contacts framework answers. Fix: deep link to the exact pane, with a picture.

3Your mail and calendar

Google sign-in, read-only, one or more accounts. The consent screen shows the unverified-app warning until Google's review lands; the screen says so in plain words and shows the two permissions being asked. Check: token file written and one messages.list succeeds. Fix: retry, or skip with the card working from iMessage alone.

4Who you know professionally

Drop zone for the LinkedIn data export, with the four-click path to request it. Check: Connections.csv parsed, count shown, tags derived (investor · founder · operator counts). Fix: skip; modes stay at "any" until it arrives, and the drop zone lives on the connections page.

5How it reads

The engine. Check: is the Claude CLI installed and signed in (one claude -p ping from the app)? If yes: "Use your Claude subscription for reading and drafting", off until tapped, with the plain sentence about what leaves the Mac. If no: download the local model sized to this Mac's memory, and say what that costs in disk and battery. Writes relationshipMemory.engine. No engine, no pages; the card still serves from counts and quotes.

6First load

A live table: source · rows · people who wrote to you · status. Mail shows its backfill estimate from measured rate. The sweep and page builder start on the eligible pool as soon as identity settles. The screen ends when the first card is servable and shows it. Check: every connected source links more than zero people, or the row turns amber and says "connected, nobody found yet" with a report button. This check would have caught the Gmail bug on day one.

Removed from onboarding: the typing demo, the widget spotlight, the model tier picker as a mandatory step, the "unify your circles" ring. Nothing is deleted; the screens stay in the file behind the same flag as their features.

One person, no modes (2026-09-13). The owner dropped the any/founder/investor picker: reconnect is one person a day from everyone. A rejection ("not relevant", "mute 30d", "never", "not this kind") is the owner pulling, not the app interrupting, so it does not spend the day's card; "show me another" serves the next candidate up to three times a day, then "that's enough for today". "Will text them" ends the day. The mode machinery stays in the code behind the timeline flag.

Judgments move to Jev (2026-09-20 to 21, v0.6.0). Owner decision, verbatim intent: value over the off-by-default promise; judgments are on whenever a TypeSafe key is present, and kind ships from Jev. Three evals on 54 judged cards drove the shape: twelve raw lines gave AUC 0.58 on "would the owner accept this reminder", a code-built state of the store's facts rendered as words gave 0.72 with monotone calibration, and dropping the words flipped the relationship read from friend to business for 40 of 54 people, so kind is two scores (professional axis, closeness) plus relative and romantic flags with the label derived in code. Shipped: the client with a hard-coded host, a 24k-token refusal, latched 401, a 15-minute circuit and sanitized numbers-only answers; the judgment pass beside the producers writing a 90-day cache the serve reads through one resolver shared with the gate; quote as the best line at or above 3 of 4 or none; worth as the leading rank bucket; the derived kind as the writer of people.role and the mode-any exclusion at serve time; a distiller prefilter that fails open; a settings row; the eval script in the tree; contact-card facts, tapback tallies and one-on-one meetings in the state. Two contrarian review rounds, 13 findings, all fixed. Left for a later release: the sweep's sub-role and firm as a choice over code-extracted options, and quote-only person-page sections.

From scratch off the released DMG (2026-09-14, recorded). v0.5.1 installed from its DMG on this Mac with every grant revoked and both defaults domains deleted: screens 1 to 6, Full Disk Access by the owner, Google sign-in through the unverified-app path, LinkedIn "request a copy" then "later", the Claude probe, and the first card about eight minutes after the FDA grant; Messages read within a minute of the grant; the export offer imported 2.8k connections in a second. Four first-run faults came out of it and are fixed in 0.5.2: the reader started at launch with an empty config, so Calendar and Contacts asked over screen 1 instead of screen 2; a pre-rename defaults domain marked a wiped home as onboarded, so the daily cap was never written; the export offer was drawn behind the reconnect card; and an install whose plists survived a wiped home never staged node, so hermes sat at EX_CONFIG and sign-in could not work. Five review rounds and four live launches on the fixed build: screen 1 without dialogs, agents reloaded after a bootout, node staged with old plists present, and agent pids stable across relaunches.

LinkedIn, request now and import later (2026-09-13). Run 8, recorded: screen 4 opens LinkedIn's download page in the browser with the two routes spelled out (the pick-list does not always offer Connections; the larger archive does), "later" continues, the first card arrives from anyone under the held investor pick with the line saying so, the app notices the export zip appear in Downloads and offers it in its own panel, one press imports it, and the pick takes over as soon as the profiles are read. Also from these runs: settings is one line per row with quit, uninstall and the Claude toggle; the People door is behind the timeline flag; the card carries title and company, who wrote last, last meeting, and a quote with a quality floor.

Two things the runs settled that the plan had left open. The reader must sprint through last year on a fresh Mac or the card cannot exist — the pool wants someone quiet 180 days, and only history can contain them; the sprint reads local stores only, for at most half an hour, and mail trails behind it. And a fresh install in investor mode may have no quiet investor yet while "anyone" has several; screen 6 now says so with the counts and offers to start with anyone, leaving the mode the owner's.
